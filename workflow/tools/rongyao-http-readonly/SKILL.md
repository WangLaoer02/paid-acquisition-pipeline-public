# 荣耀无浏览器只读

发布入口是飞书工作流中心“荣耀工具”下同名章节。本目录为现行manifest所列版本的可执行源码，Codex与OpenClaw链接同一目录。

## 执行入口与能力

机器差异、账号复用、撤销与恢复选择统一按已安装的 `rongyao-keyring` Skill；本文件维护HTTP协议及接码实现。日常直接执行以下原命令，不先运行Chrome的ensure-query。路径使用当前安装目录下的scripts。

| 目的 | 执行器 | 覆盖范围 |
| --- | --- | --- |
| 视频列表首页 | rongyao_http.py video-list | first_page_only |
| 分类117产出/列表分页 | rongyao_http.py query --filters-json | weekly_query白名单内筛选和分页；全量需逐页核验并按ID去重 |
| 火影普通素材CSV | 主查询Skill → material_performance.py → market_export_cli.py | gid=193、tenyear、mid；项目、双日期与字段由返回结果验收 |

市场适配器不支持的维度在提交前交回主查询Skill选定兼容桥；不通过丢参数或失败后换入口重放实现。

## 默认执行

以下自动取码步骤只适用于本机已采用自动短信的路径（当前MacBook）；Mac mini既有人工/群备用继续原入口，不以本节改选认证方式。各机器都先复用服务或恢复本机Keychain，实际网站会话失效后才进入该机器原认证分支；日常不做额外短信预检。

1. 用本Skill的 `scripts/rongyao_http.py status` 查询本机服务。返回ready后，执行 `video-list --session <返回ID> --output <结果路径>`；真实列表成功才算完成。
2. 无可用会话时执行 `start --output-dir <本次目录>`。默认短信自动登录：现有受信任Keychain助手注入原账号密码；请求一次验证码；从Mac信息只读获取本次新短信；自动提交登录；进入广告后台读取首页并启动可复用服务。无需用户复制验证码或扫码。start本身也先复用有效会话。
3. 服务默认最长24小时，仍受网站自身有效期限制。Cookie由固定原生助手安全保存在本机Keychain；服务退出先恢复并核验，网站确实过期才沿原短信自动登录。另一个进程或聊天可用status发现服务。
4. 按用户2026-10-23明确要求：自动取码不限制发送号码或短信用途文字。仅检查本次发码后60秒内到达、ROWID晚于请求前基线的入站新短信，从中识别独立六位数字。唯一候选码时使用；多个不同候选码时停止自动选择，相同码重复短信不算冲突。60秒后停止等待，不读取历史短信、不自动重发。验证码只留内存。

用户已选择短信作为默认方法。飞书二维码代码仅保留协议诊断兼容；只有用户明确要求改用飞书扫码时才可使用 `start --method feishu-qr`。失败不得自动展示二维码或要求用户扫码。

## 安装和故障

安装、原生依赖按[安装说明](README.md)。旧来源绑定现仅作历史元数据，不再作为自动取码前置条件；配置只留 `~/.codex/state/rongyao-http/sms-source.json`，安装包不包含它。换电脑先检查现有钥匙包和短信同步权限；缺少时报告具体缺项，不导出原账号、不更改系统权限。新电脑不能仅凭解压安装包宣称认证可用。

钥匙包结构变化返回KEYRING_STRUCTURE_CHANGED时停止；短信扩展只临时增加一次性分支，进入受信任进程后立即恢复原代码，结束时再次核对。异常恢复及实际接口合同见[协议](references/protocol.md)。不改原上传、生成、writer或业务节点合同。

## 验收边界

video-list首页结果标coverage=first_page_only；query分页按实际读取页验收，不能沿用首页标志声称全量。按同卡片ID和唯一名称配对，并核对总数；登录页、总数非零但记录为空、重复ID或歧义名称均报错。后台总数是当前可见列表口径，不是本人产出，也不代表全部分页已读取。播放、详情、上传、生成与投放各自验证。

本机服务开放status、video-list、原有限定query、refresh、stop；元数据及socket位于0700目录，文件权限0600，不含Cookie。账号密码只由既有Keychain助手注入消费进程；验证码仅在内存中处理，不写入源码、聊天、日志或安装包。短信接口只读，登录POST限定门户原生sendMessage和login动作。全程不启动或连接浏览器。

发布验证事实见[verification.json](references/verification.json)。同一会话复读不代表新登录；新登录、新安装目录和独立进程复读分别记录。

## 本机免短信恢复（2026-10-23）

用户已授权将本机有效HTTP登录态安全持久化。日常直接执行原命令：优先复用当前服务；服务退出或满24小时后，从本机独立Keychain会话条目恢复并核验实际受保护入口，不发验证码、不提交密码。网络错误和权限错误不当作登录过期。网站确实撤销会话后，才沿本机原自动接码登录；仍只发一次，不自动重发，不改60秒唯一新短信规则。不会从别的电脑复制账号或Cookie。

会话仅由固定原生助手通过私有管道读写`com.codex.rongyao-http-session`下readonly／upload独立条目，磁盘、socket、报告和安装包无Cookie明文；原账号Keychain程序与条目保持不变。查询、市场导出、上传票据与账本及受理未知处理沿原合同，不因恢复而重放查询或上传。状态内cookies_persisted=true且受保护读取成功才算当前可用，跨天效果另验。

本机实际验证：2026-10-23，查询原命令及上传fields各通过两轮停服自动恢复，原市场受保护入口也通过，全程未发短信、未提交密码、未上传视频。登录态来自本机原HTTP进程；原账号助手哈希不变。跨天效果待另行验证。纯SSH环境读取登录钥匙串可能返回-25308；已运行服务可直接复用，冷恢复应在本机已登录用户的桌面环境执行原命令。这是系统交互环境限制，不当作网站掉线，不据此重发验证码，不自动解锁钥匙串或修改ACL。

## 显式初始化与撤销


本机已部署独立会话助手；其他机器未部署时继续原登录路径，不要求更改其自动/人工接码选择。新机器明确启用时运行`python3 scripts/session_store.py build`一次；已有助手不静默重建。`status --service upload`只显示保存状态，不读取或打印Cookie。`forget --service upload`清除该会话，不改账号密码；原keyring disable仍阻止后续恢复。

首次尚无保存会话时，现有正常认证成功即自动保存。本机明确做认证初始化而没有待上传批次时，可运行`python3 scripts/session_store.py initialize --service upload --output-dir <本次目录>`：继续使用原受信任账号助手和正常短信登录，仅这一次在本机隐藏输入窗口输入验证码；不制造上传批次、不授予上传权、不替换原群接码备用入口。日常业务不运行initialize。`restore --service upload --output-dir <本次目录>`只尝试保存会话恢复，不发验证码。

自动接码只用于该机器已采用的自动路径；Mac mini原人工/群备用与MacBook原自动接码分别保留，日常不因新版改选认证方式。

## 1.3.2 恢复失败原因保留

恢复动作在原HTTP状态目录保存每个服务一份脱敏restore-<service>-status.json，记录实际验证错误、是否清除保存会话及检查时间。只有确认门户登录失效的LOGIN_EXPIRED／RONGYAO_LOGIN_UNVERIFIED才清除；需求端登录、网络、权限或页面结构错误保留原会话。进程退出本身不清除会话，不触发短信。

## 1.3.3 门户与失败原因接续

上传空闲刷新同时沿原同账号门户与广告链接读取，保持后续需求端详情SSO所需的门户会话；只读GET，不发送密码/短信、不重放视频提交。最新恢复诊断保留最近一次明确门户认证失效原因，即使后续空会话轮询也不抹去，便于定位。平台真实失效仍沿本机原验证码路径。
