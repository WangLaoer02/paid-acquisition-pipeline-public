# 审核报告与证据合同

## 范围与阶段结论
在原项目维护位置写一份本次报告；已存在同一审核记录时更新原记录，不另建重复台账。未指定且无法解析存放位置时先在当前回复交付，测试产物留授权隔离目录。报告不是被审工作流的运行规则。
报告记录：目标入口、正式版本/提交/哈希、运行环境、审核模式和范围、实际检查时间、获准动作、非目标。R01至R06各有一个结论及证据/缺项，保留同一目标版本的续接标识。
每项结论只能是：通过、不通过、待验证、不适用。通过须有适用证据；不通过须可定位具体违反；待验证写缺条件及下一步；不适用写业务理由，不能用来掩盖权限不足或尚未执行。
分别给出结构可用、运行可用、生产可用。必要要求中存在已证实阻塞则对应层级不通过；没有已知失败但必需测试尚未执行则待验证；所有适用必需项有证据才通过。不用综合评分抵消关键缺陷。

## 问题记录
每条问题含：稳定ID、严重性、位置、违反的当前要求、实际观察、证据引用、影响范围、建议归属、最小修复、复验用例。严重性分阻塞、重要、建议；建议不能冒充已证实故障。
原话、工具结果与推断分别标注。引用源码/文档的真实位置和版本，不编造行号、链接、测试ID或授权。输出脱敏且可回读的证据，不保留Token、Cookie、临时签名URL及私密思考过程。
必要日志只记录可观察输入、调用、输出和结果；无用途的完整会话、内部推理、重复回执不归档。证据缺失时报告未验证，而不是生成看似完整的成功记录。

## 输出格式
审核对象：入口、版本、环境、范围。
阶段结论：R01锁定对象；R02结构依赖；R03规则质量；R04读取执行；R05安全恢复；R06结论修复。各项填写四态之一及证据/缺项。
分层结论：结构／运行／生产。
已证实问题：ID、位置、证据、影响、最小修复与回归。
未验项：缺少条件、受影响范围、下一次具体动作。
修改与发布：未修改／隔离候选／已授权修复／已发布，并列真实回读依据。
保护与恢复：原件保留、用户手改、外部副作用、回退位置及下一步。

## 复用与发布限制
报告完成不等于修复完成；候选通过不等于正式发布；发布成功不等于业务或用户采用通过。无需发布或用户仅要求审核时，R06以报告和候选是否完整为准，不要求为了“通过”擅自发布。
后续维护只从已核验问题提出最小规则差异；无新证据不改正式版。审查框架自身也适用这套方法，但自审不能冒称独立认证。
