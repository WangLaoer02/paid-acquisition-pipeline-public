# 小剧场创作母 Skill｜通用元协议 v2.0

当用户提出小剧场创意、故事、剧本、分镜、拆解、改写、制作或新建专项 Skill 的请求时，先理解用户目标，再按本协议选用适用专项。**本地文件可离线阅读**，Notion 是在线维护入口。

## 工作流调用接口

由工作流调用时，接收当前参考范围、原片事实与判断／未知、用户限制、任务阶段和交付数量。创意阶段主动补足可修改的人物、场景、动作和变化，不把待核事实补成真；给实质不同的候选，用户单方案优先。指定框架优先，先核本地真实入口；本页的悬疑、情感等名称仅为方法类别，不证明对应Skill已安装。普通方法可组合，不能把参考反向套入模板。

管线节点决定当前停点与产物粒度；创意预演只呈现必要画面文字，不因读取本Skill执行完整剧本、分镜、生成或外部写入。路由是指导执行模型选择方法，不是程序自动调用创作模型。依赖manifest校验本地版本和SHA；路径目录及接入模板按需读。

## 基本工作方式
1. 提取本次任务的目标、要素、体验、组织、形式和验收要求（D1–D6），缺失项不默认编造。
2. 选择一个主专项，可根据明确需求叠加 IP、分镜、广告或模型执行模块；没有可用专项时通用处理。
3. 专项的特有结构仅对其适用场景生效，不污染其他创作模式。
4. 输出符合本次请求的成品，不必展示内部路由、映射和自检。
5. 验收只检查与本次目标和选中专项相关的要求。

**适用范围**：所有小剧场的创意发散、剧本、分镜、改写、拆解、评估与专项 Skill 构建。用于跨题材路由、规则组合与验收；不强制使用任何具体 IP、人物关系、叙事模式、风格或商业形式。

> 
**核心职责：**母协议只负责「理解任务 → 选择专项 → 组合规则 → 生成 → 校验 → 交付」。真正的偏心、悬疑、情感、荒诞等方法由子 Skill 定义。


## 0｜定位与边界

**定位：管理创作，不替专项创作。**

本 Skill 是所有“小剧场专项 Skill”的上层调用协议。它回答：

- 用户想得到什么？
- 哪些信息和规则必须遵循？
- 哪个专项最适合处理？
- 专项之间如何组合、冲突时怎么取舍？
- 如何按任务目标验收并交付？

不默认：火影或任何特定 IP；必须冲突、双标、反转、反杀、三幕式；必须夸张、热点、网梗或第一帧强冲击；固定秒数、对白数、场景数；游戏广告、口播或转化；必须有完整叙事。单笑点、氛围、视觉奇观、开放结局和连续片段都可以成立。以上均由用户要求、适用子 Skill 或资料确定。

## 1｜六大通用维度（信息轴，不是剧情六步）

| 维度 | 核心问题 | 可接入变量 | 母协议原则 |
| --- | --- | --- | --- |
| D1 创作目标 | 为什么创作？ | 用户意图、观众、平台、传播/情感/叙事/展示/转化目标 | 必须识别，不预设结果 |
| D2 内容要素 | 使用什么材料？ | 角色、关系、世界、事件、信息、参考、道具、规则 | 按任务选择，可为空 |
| D3 体验机制 | 观众为什么看？ | 好奇、幽默、共情、冲突、恐惧、爽感、奇观、认同、知识、气氛 | 不预设某一种 |
| D4 组织方式 | 体验怎样展开？ | 线性、倒叙、递进、并列、对照、循环、揭示、蒙太奇、单事件、开放式 | 不固定结构 |
| D5 表现形式 | 怎样呈现？ | 时长、文本、对白、动作、分镜、镜头、音画、风格、人物数、制作资源 | 遵循请求 |
| D6 验证标准 | 怎样验收？ | 目标契合、清晰、独特、连贯、设定一致、制作性、商业准确 | 只检查适用项 |

**不要把不同信息轴误当成同级题材**：婚闹属于社会情境/内容要素，偏心属于关系与体验机制，反转是组织手段，竖屏是表现形式，买量是创作目标。它们可以组合，而非互斥选项。

## 2｜核心操作：任务识别 → 路由 → 生成 → 校验 → 交付

### 2.1 任务识别

按用户显式信息提取：

- **任务动作**：发散创意、剧本、分镜、改写、拆解、评估、归纳规则、构建新 Skill。
- **任务目标**：希望观众或业务获得何种结果。
- **限定信息**：IP、角色、题材、情节、参考、卖点、平台、时长、风格。
- **禁止内容**：不得改变的部分、不能使用的结构、场景或规模限制。
- **交付标准**：数量、格式、细节深度、优先级。

未指定细节保持「未指定」，不自动套入用户历史上喜欢的题材或固定套路。没有重大阻碍时，用可修改的轻量默认值直接完成任务。

### 2.2 子 Skill 路由

优先选一个**主专项**；必要时独立叠加：

- 题材/机制模块：偏心双标、悬疑误会、社会讽刺、挑战闯关、情感日常、纯视觉荒诞。
- 世界/资料模块：火影、咒术、原创、历史、产品资料。提供事实，不决定情节结构。
- 形式/制作模块：竖屏、无对白、舞台对话、分镜、AI 视频制作约束。
- 目的/投放模块：纯内容、游戏买量、品牌传播、知识表达；广告仅明确需要时调用。
- 评估/迭代模块：拆解、诊断、迭代、对比、差异化发散。

不要为了“用尽模块”而强行添加剧情元素。没有匹配专项时可按母协议完成一般创作，不要虚称调用了不存在的 Skill。

### 2.3 生成

使用子 Skill 定义的创作流程。母 Skill 不强加首帧钩子、起承转合、三幕式、四拍结构、反转或强结尾。

通用最小约束：

1. 输出对应用户本次任务和交付物。
2. 角色、事件、情绪、画面、信息的关联程度，应满足该类型预期；故意荒诞、非线性、开放式不是逻辑错误。
3. 不编造产品事实、真实数据或未经核实的流行趋势。
4. 不硬插用户未要求的 IP、角色、数值或卖点。
5. 用动作即可表达的任务不强写对白；靠氛围成立的任务不强写冲突。

### 2.4 校验

先验是否完成本次任务，再验专项指标：

- 任务契合：是否交付创意/剧本/分镜/改写/拆解等。
- 观众效果：笑点、悬念、情绪、奇观或信息是否得到有效支撑。
- 表达清晰：必要信息可理解，刻意留白不能直接判为失败。
- 内在一致：人物、设定、风格、逻辑相互兼容；有意打破设定须服务于创意。
- 独特性：不是简单换人名或台词，具有新机制或表现。
- 落地性：符合用户明确的制作条件，未指定时不强加成本。
- 事实/商业准确：涉及 IP、历史、游戏卖点、投放数据时才核验。

**不可用某个专项的要求否定其他故事类型**：没有反杀不代表悬疑失败；没有冲突不代表视觉喜剧失败。

### 2.5 交付

| 任务动作 | 默认交付 |
| --- | --- |
| 创意发散 | 差异化创意候选 + 各自机制 + 可视化切入点 |
| 写剧本 | 可直接使用的剧本；不插入无关过程说明 |
| 做分镜 | 镜头画面、动作、对白/声音、时长/转场（按需） |
| 改写迭代 | 保留用户未要求改变的部分，实质解决目标问题 |
| 拆解复盘 | 素材构成、机制、观看体验、复用条件；效果只凭数据 |
| 构建 Skill | 可复用规则、边界、输入输出、调用与验收 |

用户指定字数、格式、条数、只要正文时，以其要求为准。默认不公开内部路由过程或自检。

## 3｜子 Skill 统一接入接口

每个子 Skill 应说明；不适用的项目写「无/未指定」：

1. 职责边界：解决什么、不解决什么。
2. 触发与排除：何时启用或不启用。
3. 六维映射：D1–D6 分别负责、补充或不干预哪些轴。
4. 输入接口：必需、可选、默认、禁止。
5. 核心机制：独有的创作方法、叙事机制或视觉方法。
6. 执行规则：具体选材、构思、推进和表现。
7. 可变参数：角色、场景、时长、视角、结局等。
8. 约束项：IP/事实、制作、平台、用户锁定要求。
9. 输出接口：成果类型、格式、粒度。
10. 专属验收：仅检查本专项有意义的质量标准。
11. 组合与冲突：可叠加项、不可共存项、取舍策略。

专项写自己独有的方法，不需要重复母协议。可使用本页下方《子 Skill 接入模板》。

## 4｜优先级与继承规则

适用的安全、权限、工具约束始终优先。在可执行范围内，创作规则从高到低：

1. 用户本次明确要求与不可更改条件。
2. 本次指定专项、参考作品、产品与设定事实。
3. 母 Skill 的任务管理、事实边界与交付原则。
4. 子 Skill 可覆盖的默认做法，如字数、时长、角色数、节奏。
5. 一般创作惯例与未确认偏好。

**局部生效**：未启用偏心专项则不继承“必须补刀、反向怪罪”；未启用游戏广告则不继承战力或首充；未选火影 IP 则不继承写轮眼资料。

组合冲突时先保留用户硬约束与主专项核心机制，辅助模块降为可选素材；不得机械叠满所有规则。

## 5｜三层架构

**第一层：母协议（固定）**——六维信息结构、任务路由、优先级、执行和通用验收；不设统一剧情公式。

**第二层：子 Skill（扩展）**——特定题材、体验机制、表现形式或目的的创作方法。不同模块可以正交叠加。

**第三层：项目数据（可替换）**——角色、IP 设定、参考视频、产品卖点、平台规范、投放数据和制作资产；它们是事实依据，不是普适规则。

组合示例：

- 火影资料 + 偏心专项 + 买量承接 → 偏心广告小剧场。
- 原创人物 + 情感专项 + 双人对白 → 生活短剧。
- 悬疑专项 + 倒叙结构 + 无台词视觉 → 默片悬疑。
- 神话资料 + 挑战/任务模块 + 喜剧风格 → 神话挑战。
- 单笑点专项 + 动作表演 → 不要求完整冲突/反杀的视觉喜剧。

## 8｜总原则

**母协议负责「理解、组合、执行、校验」；专项 Skill 负责「如何创造特定体验」；项目资料负责「内容的真实性与独特性」；用户本次要求决定「交付什么」。**

创作目标变化，母协议不变；题材变化，替换子 Skill；IP 或产品变化，替换项目资料。
