## 继续当前工程

当前工程路径从本项目控制台读取；首次案例复现使用案例包重连后的工程。先核对项目编号与版本，不创建其他用户目录。

1. 先inspect当前工程内存与磁盘；有未保存修改时按premiere-automation.01原生snapshot-copy保存在全新副本，回读后再进行本次修改。PR是当前后期剪辑事实来源，timeline.json只同步必要素材、状态和交付数据；不得按旧JSON重建覆盖。
2. 只有需要离线py-premiere编辑时才在已保存的备份候选上处理，避免原工程旧内存覆盖；写回前比较源SHA，冲突重新读取。原生检查／保存／导出沿当前桥，不以关闭工程作为所有操作前置。
3. 回读比较非目标视频、对白、字幕、转场、静音和入出点未变；重新打开PR确认。每任务一个当前工程、一个主序列，内部多视频轨、完整原片与备选保留，采用片段在上。添加、备选、替换按用户意图，不固定轨道编号。
4. BGM默认一条原曲连续区间，正常速度，不按场景跳段、循环或中段淡出。保留完整音源与独立可编辑音轨，音量服从对白；不能把本次音乐起点推广为所有项目固定值。
5. 字幕字体、字号、换行、边距和时间卡按当前已确认包装要求；历史SK002的720P／105号／SourceHanSansCN-Bold不作为新任务默认。文字与实际对白对应，时间卡是否朗读按当前声音方案。
6. PR原生导出前再保存，使用当前主序列与最新Source In/Out，不能沿用历史25/27.5/29秒。编码、画幅、分辨率、帧率、音频和字幕烧录按A09同版方案与当前主序列，核实预设；不能用历史720P覆盖已确认规格。执行路径按当前A13接口优先规范：优先已验证UXP IMMEDIATELY原生直导；GUI仅兜底，AME队列不代替本流程PR直导。
7. 确认编码完成、文件非空，ffprobe检查音视频流与实测时长，ffmpeg完整解码，抽查字幕/时间卡/结尾。机器检查、实际听审和用户采用分别记录。FFmpeg另做的审核片不能冒充PR导出。

## 补镜生成

先看真实素材，再确定目标状态。仅需造型或声线时不带整条含旧剧情的视频；反应补镜优先用人物同框、道具与情绪正确的关键帧。首帧或多模态模式服从当前CLI/model规格。回读真实引用后报价；按用户对应授权生成，保留公开node/submit/resource身份。下载后实际画面与语音核对，错镜头或错对白标待修复，不能改字幕掩盖。重生成不自动追加消费。

补镜沿A09当前已确认平台、模型、画幅和规格；未指定时仅由当前video-prompts.01提供项目默认，单次时长核实时模型目录。用户明确指定较长项目或分段时，后期总长服从用户。提示词只写可见画面、动作、对白与必要约束，不夹规则、检查过程及未绑定占位符。

## 本机工具与历史脚本

py-premiere负责工程最小修改；FFmpeg负责解码、恒帧副本、A导出后的接B与检查；faster-whisper辅助转写，不能证明实际听审；WhisperX只对已核对文本对齐。音频先用FFmpeg解码为数组，避开容器接口兼容问题。

`run.py all`与`build_source_music_pr.py`是固定旧版25秒的历史重建器，含分段配乐和旧字幕，不适用于当前交付或新项目。默认拒绝历史重建；仅用户明确要求历史复现时传`--legacy-rebuild`及独立`--output`，目标已存在仍拒绝覆盖。不要为了续编生成另一套主工程。

不创建思考文本、重复主控或过程流水。保留必要源素材、可编辑工程、最终导出、备份和最少恢复证据；不存凭据或临时签名链接。

## 本地素材库

素材库目录从当前项目配置读取；从 `index.html` 检索预览，`README.md` 查看命名及入库命令。本案例项目为 `SK002`；新项目独立分配编号。下载后检查实际内容，按项目编号、类别、用途及V三位版本复制入库并校验哈希；相同字节去重，已有版本不覆盖。新素材从库内导入PR，现有工程引用原路径保持不变。库内目录仅管文件，不替代飞书中心规则和项目表状态。

续编前先检查交付说明与timeline是否为旧快照；本项目旧记录仍含分段配乐和旧时长。只以最新保存工程确定剪辑事实，实际文件确定导出规格；未核对的新状态不填成通过。完整生产步骤和已验证经验统一维护在飞书中心主控。

## 转写模型复用

快速转写入口不可用时，先检查已安装faster-whisper环境和Hugging Face snapshot的符号链接目标，不仅搜索顶层model.bin或.incomplete文件。精确模型路径从接收者本机配置取得；核对model.bin以及config/tokenizer/vocabulary是否齐全。执行前重新核验，使用精确本地路径和local_files_only，成功加载后再转写；文件存在不等于运行通过。不要调用历史run.py all获取转写，不重复下载已完整缓存的权重。无可用模型时明确声音待验，OCR不替代声音核对。

## PR导出A段与FFmpeg接B段

本工作流固定分工：PR制作并原生导出A段；FFmpeg用已验A段MP4接游戏B段，输出各版完整广告成片。PR原生导出要求适用于A段，不扩展为每条接B成片都须进入PR。只要求导出时先读取最新保存工程，不重建剪辑。已有A导出与最新工程、Source In/Out及实际内容一致时直接复用；A有手改才重新导出。

A13—A15保持可编辑PR、唯一主序列、A段原生导出与验收归档。B01核对采用A及B来源、版本和实际切点；B02用FFmpeg配置接片、画幅、帧率、转场、混音、标语与运动水印；B03由FFmpeg编码完整MP4并记录A/B输入SHA、入出点、参数及输出；B04逐条检查画面、完整声音、接点与片尾；B05归档并反链A。接B默认不新建PR工程、不把B/标语/水印导入PR、不为接片调试嵌套序列或PR透明通道。用户明确要求接B可编辑PR或PR接B特效时才走该例外，并记录范围。

保留A实际画幅与帧率，B适配不裁掉关键人物、文字和既有包装。完整A后接所选B的有效区间，不套历史切点；先检查已有标语/运动水印，补缺且不重复叠加。响度先测量再调增益，不套案例数值。每版完整解码并单独看接点/片尾、听完整音轨；A检查不替代B检查。无音轨A按已确认声音方案处理，不自行补配音或音乐。A标“PR原生导出”，接B标“FFmpeg接片成片”，分别保留来源，不混称。历史脚本只复用已核实方法与参数结构，不直接重放固定路径。先提供可审看的成片，再集中归档回填；归档与用户采用分别计。

## 连续操作失败后的纠偏

桌面或浏览器操作以目标状态变化判成功；工具返回成功不等于点到了目标。第一次失败先刷新当前窗口/页面、焦点、活动工程/序列、弹窗及截图/可访问控件；仅依据新状态调整后重试一次。同一目标连续两次失败（点击无效、错误控件/工程、黑画面或状态不变），立即停止该组点击/快捷键，不换坐标继续盲试。

重新核对最新用户要求、当前节点、同版规则、已有产物和已验证执行入口；定位为目标/焦点错误、输入/工程错误、接口能力不足或真实权限/登录问题。只在有可观察的新依据后做一次纠偏尝试，逐步确认目标状态；仍失败则报告具体阻塞、已完成产物与可继续步骤，停止该界面分支并继续独立工作。失败计数在确认目标成功后才重置，切窗口/换快捷键不重置。PR导A失败不能用FFmpeg冒称原生导出；接B失败回FFmpeg配置，不转入PR研究嵌套/透明通道。安全拒绝、受理未知及费用授权沿原规则，不以纠偏为由换通道或重复提交。

用户提醒“做法不对/之前怎么做”时，先暂停被质疑路径，读取真实历史脚本、回执与当前规则，说明差异再继续；不把本轮猜测当作历史事实。用户最新明确路径优先，规则冲突在维护处修正，不要求用户逐次纠偏。仅在现有检查点记录失败类别、证据、纠偏结果和下一步，不新增思考或重试流水。


## 接口优先与范围

按当前节点的premiere-automation规范执行检查、保存、原生直导与实际验收。未验证接口不标可用，直导回执绑定实际保存工程及范围，完整日志留磁盘，AI只读取必要结果。

## 新工程轨道方案与实际能力

新工程按内容需要安排：V1原片／备选（关闭显示），V2采用画面，V3字卡／包装；C1原生字幕；A1对白／采用原声，A2连续BGM，A3音效，A4备用原声（静音）。缺少该类内容不强制填轨；续编沿原轨道，不为编号重排手改。记录实际轨号与用途，并回读可编辑性、开关、静音及有无重复音频。

这是新工程设计约定。当前UXP桥提供inspect、snapshot-copy、open-copy、export-a和restore-original，不提供一键创建上述轨道；剪辑及轨道变更由现有py-premiere或已授权PR操作完成，按本机接口实际支持核验。不能将桥检查成功称为分轨已完成；全套轨道新建及C1恢复仍需在接收机真实工程验收。
