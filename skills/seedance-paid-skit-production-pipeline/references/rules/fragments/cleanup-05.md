## 无损修改与指令派生
- “只输出成品”“前台简洁”“不要过程说明”约束交付展示，不授权删减 Skill 的实现、触发条件、角色映射、有效示例、参考库、异常处理、重试策略、授权边界或验收标准。文档更短、版本号更高不代表能力更完整。
- 修改前完整读取目标正文、必要依赖、当前指针与基线；遇到截断、未知块、无法访问的依赖或来源冲突，保留原内容并标 REVIEW，不从搜索摘要重建正文。
- 按最小语义单元记录“原条款 → 保留位置／等价条款／用户明确授权删除的依据”。清理目标之外的原文不重写；重复项只有在条件、例外、效果一致且目标可访问时才可合并，互补内容不算重复。
- 规则、例外、必要示例、引用、输入输出、数字阈值、失败恢复和权限约束逐项核对，未授权语义删除与未授权新增默认要求必须为零。只把全文缩成摘要、把方法示例换成原则、把可选改成必选，均不属于清理。
- 从用户请求派生维护指令时，区分用户原话、适用对象、允许的操作和 Agent 推导；推导不能扩大删除范围，不能把一次项目要求提升为全局规则。原始请求、派生指令与变更对照保存在独立审计记录，不写入业务执行正文，不保存私密思考过程。
- 修改前保存可回滚原文或精确逆向补丁。默认精确更新；不覆盖历史版本。移到参考文件的内容须在原执行路径提供明确、可访问的按需读取入口；移走不等于保留成功。
- 先核验新正文和依赖，再核验可下载 `SKILL.md`、本机／仓库入口与当前指针。正文、附件或指针不一致时，不宣称同步完成；保留旧件作为历史，不让未验收的新摘要自动接任 Canonical。
- 回归检查至少覆盖：清理“本轮自检通过”日志但保留自检标准；删除一次上传重试流水但保留失败恢复规则；隐藏角色映射的成品展示但保留生成公式与示例；精简主表但保留底层数据；默认输出仍允许用户明确要求的分析；源文件不完整时不写入。规则检查通过不冒充实际工具运行或作品质量通过。
