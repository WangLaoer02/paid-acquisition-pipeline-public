把已经确认的剧情翻译成**可以直接拍、画、生成、剪辑的镜头脚本**。
成熟分镜约：
> **80%可见动作 + 20%情绪目的**
“悲伤、愤怒、紧张”不是镜头，必须转换成观众能看到或听到的变化。
## 每镜头必须回答
1. 人物在哪里？
2. 做什么？
3. 看哪里？
4. 相机在哪里？
5. 为什么现在切镜？
## 标准字段
- 镜头号
- 时长
- 场景
- 起始景别
- 结束景别
- 构图
- 人物位置
- 可见动作
- 视线
- 台词
- 表情变化
- 机位
- 运镜
- 光影
- 环境声/音效
- 切镜原因
- AI生成备注
## 动作规则
优先写：
“右手停在门把上，回头看母亲一秒。”
不要写：
“她内心十分纠结。”
情绪需要通过：
- 停顿
- 视线
- 呼吸
- 手部动作
- 身体距离
- 音量
- 节奏
来呈现。
## 时长规则
1–3秒镜头只承担一个主要事件。
台词长度必须与镜头长度匹配。长对白需要：
- 延长镜头
- 拆镜
- 或用反应镜头承接
## 运镜规则
明确区分：
- 固定
- 推
- 拉
- 摇
- 移
- 跟
- 环绕
- 手持
- 主观
不要连续多个镜头都“缓慢推近”。
运镜必须有理由：
- 暴露信息
- 缩短关系距离
- 跟动作
- 转移注意力
- 建立空间
## AI视频优化
为了提高生成成功率：
- 一个镜头尽量一个主动作
- 复杂动作拆段
- 明确起始姿势和结束姿势
- 明确左右方向
- 明确人物数量
- 避免一镜同时完成多人物精密交互
## 输出格式

沿用[飞书分镜导演稿规则](console-format.md)的唯一列定义和分色，不再输出另一套简表。每镜创作信息按现有列组织，制作证据留项目evidence。
## 自检
- [ ] 每镜头都有可见事件
- [ ] 起始/结束景别明确
- [ ] 视线方向不乱
- [ ] 台词能在时长内说完
- [ ] 运镜没有机械重复
- [ ] 切镜都有信息或情绪理由
- [ ] 镜头编号连续

## 分镜脚本、用户改稿与成片逐镜对应

按当前阶段核验：A07完成含全部镜头和提示词的导演稿并核已采用创意及改稿影响，尚不要求未生成的最终帧证据；A08只优化关键镜头，制作中保留同一稿和素材对应；A14严验当前A文件，B04及上传前严验本次完整交付文件的逐镜／帧区间对应。以下最终交付要求不是A07的前置产物。

分镜脚本是必交付物，不能仅交剧情梗概、生成提示词或无对应关系的截图。沿用唯一项目Sheet的分镜导演稿：镜号、对照参考、分镜画面、景别/运镜、原文案、改编动作/对白、声音和时长。对照参考、原文案、改编文案保持分色；待生成或候选图明确标识。技术哈希、任务ID、版本比对和验收记录放既有项目evidence，不给母页面新增步骤或管理列。

用户可以在制作任何阶段修改分镜稿。生成前、剪辑前、导出前、上传前，重新读取唯一项目Sheet和本次明确指定的改稿文件，记录来源、原生revision及逐镜内容快照；用户最新明确修改优先。两处手改互相冲突且无法确定先后时，仅停止受影响镜头，先完成可独立核对工作。禁止用旧本地稿覆盖手改，禁止为了迎合已生成的视频反向篡改用户稿。

镜号稳定不复用；删镜保留历史，新镜取得新ID，改序不重编号冒充旧镜。比较角色/造型、动作起止、对白、景别/运镜、声音、时长及顺序。改动使对应生成输入/报价、候选、PR采用区间、导出、接B和验收待复验；影响连续性的邻接镜头一并复核，无关已验素材保留。已提交任务先查原任务，旧结果可留候选，不自动追加生成或扩大总预算。PR手改是剪辑事实；若与最新分镜冲突，应明确修片还是由用户采用新版稿，不能静默同步为已通过。

生成片段不是最终镜头。逐镜登记“当前稿版本+镜号→真实生成素材与采用入出点→PR区间→最终视频帧区间”。最终导演稿按实际交付画面展示真实截图和实际时长；A+B成片的B镜头、字幕卡和转场也必须有对应行，不能将A段验收当作整条验收。A-only按当前最终目标验，默认10～25秒；A+B在A14记录A实长及预留B关系，不要求A单独达到10秒，最终默认10～25秒按完整A+B实测总长验，明确目标优先；不得用改对白字幕掩盖错说、漏说或多说。

A14核对当前A文件全部镜头与最新当前稿的A范围：A-only即最终A；A+B此时不要求B、转场或完整AB文件先存在，B04及上传前再核完整交付文件（含B与转场）。各自被核文件均要求：镜头不多不少、顺序一致；每镜角色/造型、动作结果、对白原字、景别/运镜、声音和实际时长逐项对应。每帧均覆盖到一个镜头区间，接点不截断句子；片尾无未登记内容。图像和音轨须实际查看/听审，生成成功、转写、帧数或哈希均不代表内容通过。有任一漏镜、错镜、加戏、旧稿或未核项，标待修复，禁止声称对应、完成或上传。

机器辅助使用`scripts/storyboard_parity.py diff --previous <旧快照.json> --current <新快照.json>`标出变更；`check --root <工作区> --script <绑定稿.json> --review <逐镜核对.json> --latest <本次新读稿.json>`检查版本、证据字节和逐帧覆盖。schema见该脚本：稿为storyboard-parity-v1，镜头含id/characters/action/dialogue/camera/sound，核对为storyboard-review-v1。workflow_node inspect-evidence在A14要求storyboard_contract中script/review/latest的path与sha256。B04逐版运行上述check并保存各自结果：单版兼容storyboard_contract，多版使用storyboard_contracts数组，每项仍为script/review/latest的path与sha256，不能同时提交两种字段；每项review.video只绑定一个实际文件。inspect-evidence将每项的实际文件路径与SHA逐个对应delivery_contract交付清单，缺任一版、重复绑定、额外文件或旧证不能报齐。每版均读取并绑定最新完整AB稿；保存的工具结果只证明结构和证据绑定，不证明实际完整看听。A14的script与latest均取同一当前稿的A范围，保留原来源、revision、镜号及内容，review绑定本次真实A文件；不是把完整AB稿或旧稿任意删减以迎合视频。B04以完整AB范围及真实整片另验，不能复用A通过冒充整片通过。仍沿现有schema，不新增范围字段，不放松版本检测、全部镜头顺序或连续全帧覆盖。此辅助检查不自动抓取飞书，也不判审美或听审；操作者须在动作前实际新读，不能把旧快照改名冒充新读。审核凭据与旧稿保留，最终交付的分镜脚本和成片绑定同一版本；本地旧HTML标历史并链接当前稿，不能覆盖历史正文。
