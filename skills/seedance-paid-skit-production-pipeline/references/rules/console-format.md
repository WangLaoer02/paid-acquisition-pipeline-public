# 飞书分镜导演稿规则｜DIRECTOR-STORYBOARD-1

## 唯一输出标准

从本次发布起，新建项目和新输出的飞书制作正文统一采用 DIRECTOR-STORYBOARD-1「分镜导演稿」。以镜头为行，原始参考与改编结果并排阅读，不再生成五列控制台、整篇分场大单元格或下方管理流水。本规范完整替代此前 console-format.01—.06 的格式正文；这六个编号保留路由兼容，只加载本版内容。

原项目 Sheet 仍是唯一状态与采用来源，24 个制作节点与 Gate 不变。旧项目的内容、图片、附件、原始文案和手改不因格式发布而清空。旧模板 JSON 仅兼容已登记项目的保护性读写，不是可选的新输出标准。

## 逐镜表格与颜色

每镜一行，列顺序固定：A 镜号、B 对照参考、C 分镜画面、D 景别、E 运镜、F 原文案、G 改编文案｜画面与动作、H 改编文案｜对白、I 声音、J 时长。初建镜号从 SC-01 起；改稿保留已有镜号，新镜使用未用编号，不随删镜或改序重编号。A/B分段标识清楚，不把不同切镜挤在同一行。

B 列浅黄 #FFF4D6：原片截图或真实参考图，附来源时间点；F 列浅蓝 #EAF2FF：来源原文；G/H 列浅绿 #E8F5EC：改编内容。标题同时写明含义，不单靠颜色。C 列放粗分镜或采用画面，标明候选／采用／成片回溯；无图留空，不用重复参考图冒充新分镜。

已登记的四行表头项目保持原版；用户精简的两行版保留第1行来源、交付及阶段，第2行列名，镜头从第3行开始，冻结前两行。正文自动换行、紧凑排版并以完整可读为准；镜号沿用实际登记，删镜不重编号。不可恢复用户已删除的行。

## 原文与改编填写

原文案保留原始措辞、说话人、顺序和对应关系；只分镜分行，不替换名字、不补对白、不把剧情分析混入原文。来源跨多镜时拆分对应句；同一句只在首次发生镜填写，后续镜标“承接 SC-xx”，不重复全文。无对白的来源在页首补充说明一次，各原文格留空；无法核实的字句保留待核，不编造。

改编画面与动作写可拍摄的可见事件、人物位置和起止状态；改编对白只写该镜实际说的话及必要语气。新增动作、人物替换和对白只写绿色区域。候选与采用明确标注。景别和运镜分开，写全景／中景／近景／特写，以及固定／推／拉／摇／移／跟；只有确认后才填，不能根据单张图猜运镜。

声音只写该镜需要的对白、环境声、音效、音乐进入／退出／压低。连续音乐首镜写一次，后续只写变化。时长用秒，区分计划与实测；未知留空，不能估算冒充实测。参考图同一帧只嵌入一次，后续写“参见 SC-xx”；完整视频只在来源或交付入口出现一次。

## 正文精简与证据

正文保留制作人员需要的分镜、参考、原文、改编和声画安排。去掉重复结构总结、整段提示词、账号/UID、模型配置、费用流水、哈希、命令、执行日志、24 节点说明、版本索引大表和技术验收清单；必要执行信息放原项目 evidence 或已有资产索引，正文仅给一个相关入口。

B 段选材和接点问题在第 3 行简写；交付A+B时，B的实际镜头、字幕卡与转场也逐镜成行，按真实画面、对白和时长填写，不混入A段原文。项目阶段由原状态流程维护，不因写完文档而推进。原版事实、改编新增、采用、技术通过和业务完成分别保留证据。截图必须来自实际原片、文档或工程；回溯整理的案例明确标注，不冒充制作前已确认稿。

## 建项与保护性写入

建项先 list/context 定位真实项目，复用唯一 Sheet。新空表在 console.json 登记真实 project_id、工作簿、sheet_id、name、template_id="DIRECTOR-STORYBOARD-1" 和 shot_count（实际镜数，1—100）；通过 console_template.py init 初始化。禁止把旧项目配置改成新模板后直接 init；有内容时必须先做迁移映射并核对原引用。

写前加载 console-write，运行规则与模板检查。逐镜文本仍用 console_content.py check → patch；original_copy 对应 F、script 对应 G、dialogue 对应 H，景别用 shot_scale、运镜用 camera、声音用 sound、时长用 duration；都用 --index（从 0 开始）定位镜头。对照参考图片用 source_screenshots，分镜图用 storyboard_images，经 console_content.py image 按实际 SHA 挂载到目标工作簿并回读。

禁止单元格 note／评论／红角。原件与图片链接先保留，再核对本次目标与并发变化。文本写回不得改样式、标签、身份或阶段；图片上传未知先查原回执，不重传。写后回读目标内容、全部模板样式、非目标单元格与引用。读写失败停在受影响动作，不绕过版本守卫。

## 旧格式退役与验收

旧五列版及其“后续新项目默认”要求已从活动规则正文删除，不再与本规则并列执行。旧模板只为已有项目防错保留；历史规则备份不参加当前节点读取。既有项目尚未要求迁移时保持原样，新增导演稿不得另建状态主表；需要迁移时先读取最新正文、图像、附件、合并区和阶段，制作逐格保留映射，再在原 Sheet 经维护更新绑定和版式，禁止清空重建或恢复用户已删的管理内容。

验收只看：逐镜行完整且镜号不重复；参考、原文与改编一一对应且颜色正确；原文未改写；图与视频不重复嵌入；未知留空；声画和时长可执行；正文无琐碎管理流水；真实引用与用户手改保留。原片保真、视觉采用、听审、费用、素材上传及广告发布继续独立核验，格式通过不替代这些结论。

## 项目正文与原件保护

每项目只用原有唯一Sheet；新输出统一分镜导演稿，版式按console-format.01—.06。旧五区布局仅保护性兼容，不再作为新输出要求。分镜脚本为必交付物，提示词或时间轴不能替代；当前稿与成片按storyboard.10逐镜对应。

编辑前读取当前表头、行列、样式、合并区、完整正文、图片和附件引用。保留用户手改与原件，不按默认布局重建，不恢复用户已删除内容。新增角色、场景、特征、关键帧沿既有资产承载方式或已认可素材库入口整理，明确角色、状态和用途；容量不足先核对当前模板支持，不擅自追加图集、台账、日志或新控制台。

同一资产正文只展示一个当前版本；候选明确标候选，不冒充采用。原始文案保持原文；结构、改编、提示词与资产各自可找到，执行细节放已有evidence或索引。素材路径集中在原表，必要时只给一个真实入口。展示精简不授权删除原始资产、历史版本、验收或恢复证据；清除重复展示前先核对原件、附件、索引仍可访问。

改富文本前保存完整内容与全部图片、附件、链接引用，写后回读正文、图片数量与每个引用；不只看首图或成功回执。禁止单元格note/评论/红角。多图再做独立新读；即时与稍后读取不同则标展示待核，先单格诊断，不反复覆盖整区。不能稳定多图显示时保留原格主图和真实素材库入口，明确其余图在入口查看；原件可用与格内展示分验。界面受阻但具备导出权限时，可导出检查图片字节与锚点，仍不代替网页显示验收。
