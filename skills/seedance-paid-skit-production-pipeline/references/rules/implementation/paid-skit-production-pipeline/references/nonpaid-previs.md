# 无付费预演与复验

适用：用户排除新增费用、先验工作流，或仅审查已有工程与导出。保留完整阶段0—7和十二步，本分支用现有素材验证可执行部分，未完成的生成与正式验收继续留在原项目。

1. 从唯一项目表回读当前剧本、图片用途、提示词与首个未完成阶段。另读取当前保存PR和实际导出的制作版本、文件SHA、Source In/Out与时间。旧交付说明里的“当前”不代替实时项目；脚本变更后，只把未变依赖的旧证据继续用于对应范围。当前剧本、已产生预演、最新工程、实际导出各自可属不同版本。
2. 在原项目登记正式制作首个未完成阶段与本次验证分支，两者分开。正式剧本/图像未锁定时，仍可审查旧导出或制作明确预演；后期技术通过不补齐原片改编、能力依据、角色图、真实绑定、动作和声音。不能把旧版配音或字幕说成新版已执行。
3. 制作方沿用已有合格片段、真实场景参考、可用角色素材和已配置工具。确缺动作时用静态参考及可编辑叙事说明占位，画面明确写预演/动作待素材，记录哪些事件未被画面实际执行；不把画面文字当作动作证据。临时系统声音标来源和用途，不当目标角色最终配音，不触发付费生成。仅审核时不再制作第二份同范围预演。
4. 镜头与音轨按实际采用区间建工程：当前采用在上、原片和备选保留且备用声音静音；字幕、对白、连续配乐独立。声音先检查实际音轨或转写，再与相同版本剧本对照；明确临时声音、目标声音及主观听审。技术对齐不能掩盖错词、漏词或缺角色动作。
5. 审查同版本实际导出：完整解码、帧率、画幅、容器/音视频时长，核对字幕与接片前后连续帧、尾帧及真实游戏B来源。多接片方案各自记录启用视频/音轨与Source Out，不能用上一方案的导出范围。分开记录执行方原生打开/保存/导出证据和审核方本轮操作；独立FFmpeg渲染不冒充PR原生导出。
6. 打包或迁移按 [工程素材路径与搬移核对](portable-delivery.md) 验证。原项目正在编辑时保护其当前哈希与手改；修复候选只针对路径或实际缺陷，保持一个主序列，不另设业务主控。修复与校验完成后按已授权归档范围落位，旧包与新包版本明确，不能用候选替代未确认当前工程。
7. 审核方实际查看产物，并记录本轮看图/播放/转写/听审范围。将成功的可复用方法最小回写原Skill并回读，保留同期其他维护修改。原项目检查点写验证产物、实际通过、模拟占位、正式缺项及下一步；工作流实测完成、正式成片完成、用户采用和发布分计。

交付至少可定位：唯一项目入口、当前正式输入与被审查交付版本、可读媒体、可编辑工程、源/输出时间及音轨映射、实际检查范围和缺项。已有产物不重新生成，失败先定位到剧本、素材、绑定、模型执行、剪辑或打包，再只修受影响环节。
