# 证据类型、覆盖与来源链接

每个 finding 使用单一 `evidence_type`；混合判断拆成多条，并保留 `support_fact_ids`、`boundary`。类型表示输入来源，不能由推断自行升级。

| evidence_type | 能支持什么 | 不能支持什么 |
|---|---|---|
| backend_metric | 本次范围内消耗、付费、ROI、标签命中数量 | 台词、镜头、情节或转化原因 |
| backend_label | 后台明确标注的角色/方向/标签 | 视频真实包含该结构 |
| material_name | 名称关键词匹配、名称推断 | 已观看、内容已验证、异名结构不存在 |
| source_video | 实际观察的视频内容，附素材ID、时间位置和观察记录 | 单个镜头导致投放效果的因果结论 |
| transcript | 已读取的逐字稿/剧本内容，附文档及段落位置 | 成片画面或已播放视频 |
| user_input | 用户陈述的内容，并注明由用户提供 | 助手独立核验过的事实 |
| generated_proposal | 新写脚本、台词、镜头和测试方案，标“创作建议”、`validated=false` | 过去已经做过或已验证成功 |

名称匹配未命中写“本次口径未检出”，不写“没有做过”“从未起量”。名称、后台标签、视频核验分开统计；搜索不能排除异名同结构。

全项目查询要列出本次可见项目、实际查询项目、排除项目与原因、失败项目、枚举日期，以及投放日期和素材产出日期边界。只查当前活跃项目不等于全部历史项目。未确认枚举完整时只能报告已列项目。多个项目中同名素材分别保留项目ID；不要只按名称跨项目去重。

阈值附来源：用户确认、后台定义、Skill分析参数或临时比较阈值。临时比较阈值不能提升为业务标准；不同项目不能未经核实共用成功阈值。

缺失指标保留 null；实际0保留0。ROI1为0或缺失时倍率未定义；派生倍率与后台原始倍率分列。加权ROI按消耗权重，任何必要字段缺失时给出缺失数量，不把不完整加权数当总体ROI。后台总计、明细聚合和差额分别保留，差额原因未知就明确写未知；标签允许重叠，分组结果不能直接相加。

原始 `demand_url` 按输入原样保留，不拼接名称或补全截断参数。`source_extracted`、`url_syntax_valid`、`page_accessible`、`video_playable` 独立记录；未访问/未播放设 null。链接提取和语法合法不等于页面可访问，更不等于视频可播放。

离线快照必须标来源日期和离线状态；不能用旧快照声明实时登录验证成功。可用 `rongyao-material-performance/scripts/evidence_contract.py` 检查结构化 finding 类型与引用，但此检查不等于验证自然语言中每句话的真实性。
