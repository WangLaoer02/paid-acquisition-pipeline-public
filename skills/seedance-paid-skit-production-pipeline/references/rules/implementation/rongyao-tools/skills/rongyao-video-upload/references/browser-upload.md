执行顺序：

1. 读一次当前选中值、实际选项和radio，核对计划；同名同文件已经入库则从批次剔除。
2. 类别先选。游戏→角色、一类→二类按依赖顺序操作。其余确认独立的AI、需求人、创作类型、素材IP、第二设计师可在一个CUA调用中批量完成，只改差异；每项结果检查，不能把依赖字段和文件选择并行。
3. 读回整套选中值及file是否启用，一次比对计划。第二设计师不同的文件分组；只有所有参数一致才共用多选文件批次。
4. 在点击input前等待原生filechooser，再选该组的绝对路径。选择文件立即提交，没有另一个“保存/提交”按钮。不要先选文件再改参数。
5. 每个上传动作记录完整名、SHA、参数、分块进度及后续记录ID。分块1/2、2/2不是入库成功，也不据此再次选择文件。

所有页面交互走CUA原生locator/filechooser；`playwright.evaluate`只读DOM。不调用页面上传函数、隐藏JS状态、Cookie、网络重放或未经页面公开的接口。

## 最少回读及异常

- 按页面“约两分钟后查看”安排一次结果检查；等待期间整理本地交付，不每几秒轮询。不要靠长阻塞等待省事。
- 以完整名称匹配成功日志；日志中历史成功行不能当成本次结果。列表出现新记录ID是入库证据，已经存在不重传。
- 列表DOM本次可读：`.table-responsive input[type="text"]` 的value是完整标题；checkbox的value是ID；img的name是页面提供的详情URL。不要只读data-type=1，它代表横版，不代表所有标题。
- 详情最多一次核对角色、类别、AI、一二类、需求人、设计师、第二设计师；只读页面实际内容。游戏绩效筛选器的默认值不代表视频本身的上传游戏。
- 普通网络加载失败：保留已成功ID和进度，先读现有列表/同一动作结果；有安全可行的当前UI入口才使用。明确安全策略拒绝时不尝试其他浏览器/接口/URL编码绕过。
- 失败状态为待核对，不能改成上传成功/登录失效/审核失败。尤其不能因详情打不开就重传整条视频。
- 保存原生截图，最终回复嵌入成品列表或详情。不用修改页面HTML、加宽字段或拼造截图补证据。
