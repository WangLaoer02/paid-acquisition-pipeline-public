# Seedance 故事小剧场制作

先保证观众理解人物在争取什么、为什么冲突、谁做出决定及后果，再组织表演、镜头和美术。沿用本地当前项目及其已采用内容，尊重本次用户指定的停止阶段。

## 当前项目与范围

先从本地项目文件、已采用资产与最新用户要求确定故事、画幅、时长、声音和停止点。项目未登记时可直接在当前工作区交付故事与提示词，不要求新建云端表、网站或绑定项目。明确续接原2026-09-27故事项目时才读[原项目条件配置](references/legacy-project.md)。

视频格式、参考及参数读取[Seedance共用合同](../seedance-prompts/references/contract.md)；本流程默认按第6节五模块交付，当前明确采用精简稿时保持其有效格式。

## 1. 读人物和参考，确定一条主线

查看真实角色资料、已确认母版及最新用户修订。外形图不能充当性格证据。区分原作设定、用户自设与本篇 AU 新增项，未知处标明，不擅自添加能力、关系或全知视角。

参考改编记录四项：原作具体事件与出处、保留的因果结构、因角色性格而改变的选择、改编后的结果。仅借主播题材或情绪氛围时称主题借鉴，不冒称某个结局的情节改编。高赞、近期等判断必须有平台、日期和可核实数据。

一句主线写清：谁想做什么 → 谁因何阻止 → 主角怎样回应 → 付出什么并得到什么结果。先交完整短故事；用户已有核心情节时局部修订，保留关键动作、关系和台词。

## 2. 写完整故事，检查反差和高潮

- 开场尽早出现具体欲望或异常，不靠长篇背景解释；钩子应与最终冲突有关。
- 压缩重复过程，保留“行动导致新压力”的因果。对手也有目的和策略，不能为反转突然变傻。
- 每个节点至少改变信息、关系、控制权或风险之一。批量故事使用不同冲突机制，不统一写成受苦、牺牲、金句。
- 高潮是人物做出的可见选择、对抗或揭露，并确实改变结果；不是只写“她终于明白了”。
- 反差应能被直接看到或听到，如庆祝声与关系决裂并置；提前交代必要线索，不依赖最后一句隐喻补完。
- 允许极端选择及严重后果，但必须从角色动机推导。女性角色应能主动争取、犯错、识破或拒绝，不能只有受害表情。
- 结尾兑现主线，展示改变后的生活、关系或物件状态。无需正能量或金句收尾。
- 朗读对白并留反应时间后估时；草稿秒数不是实测。压缩时先删重复解释，不删关键因果与高潮。

进入分镜前检查：删掉名字，角色选择是否仍有辨识度？去掉结尾金句，故事是否仍完整？高潮能否用一个具体动作说清？

## 3. 按素材职责分工

| 输入 | 负责 | 不负责 |
|---|---|---|
| 角色母版 | 身份、脸型、服装、画风 | 替角色决定剧情 |
| 性格与关系资料 | 动机、能力边界、说话方式 | 锁死每个表情 |
| 场景母版 | 地点、光源、主要空间与物件 | 要求每镜同构图 |
| 单篇故事板 | 人物关系、视线、关键动作与结果 | 成片材质、每个中间姿势 |
| 视频提示词 | 时间、连续表演、台词归属、声音、必要镜头运动 | 重复描述整张参考图 |
| 后期图层 | 字幕、精确数字、屏幕文字、界面 | 替代人物行动 |

图与文字矛盾时先修输入，不能用“以文字为准”掩盖冲突。故事板与母版的不同职责可明确说明，但不能让错误手侧、人数或道具状态同时进入生成。

## 4. 时间线 → 一个故事一张故事板

先安排人物站位、视线和道具，再确定镜头。画格是剧情或表演节点，不等于镜头；镜头数、格数均按故事需要，不固定六格、九格或四镜。

默认用有体积的粗绘表演分镜：保留头部朝向、可辨表情、肩背姿态、手与道具接触、双方距离及必要背景。只画火柴人通常看不出羞辱、迟疑、试探等文戏。服装纹样、粒子与精细材质可省。用户已确认彩色版式时保留，不擅自全改灰稿。

一个故事独立一张总板，不把多个故事塞一张。整板顺序明确，图上优先编号；台词、声音、时间在配套表格，避免让长文字挤压表演画面。只修错误格及其受影响的连续性，不重做已经成立的全篇。

少切镜、简单运镜、自然过渡。能在双人同框完成的对抗优先连续演；新信息、决定性反应、空间变化或节奏停顿才切。对白不是每句一刀；情绪不是每句换一个表情。关键动作采用“意图 → 行动 → 对方反应 → 后果”，不逐帧摆姿势。

## 5. 审故事板，再决定关键帧

故事板通过后，先查现有角色/场景素材能否复用。关键帧主要在新场景或重大视觉状态改变时新增，其他情形须说明不可替代的生成控制需要。不要每个画格做一张关键帧，不把多格总板直接作为单图首帧。

新首帧必须继承已成立的物件状态和人物位置。场景没变但道具、权限或关系变了，不必自动新增美术图；先用表演、后期或连续生成解决。

## 6. 五模块提示词

沿用来源会话的顺序：**全局视觉风格锁定 → 角色锁定 → 场景锁定 → 分段剧情 → 全局限制**。用 [模板与当前案例](references/template-and-example.md) 输出。

只写影响结果的差异、易漂移点和新增时间信息。角色母版已明确的外观不反复抄写；故事板看得见的站位不逐格赘述。跨镜必要状态继承可以重复。

对白标说话人、对象、情绪和是否画外音；录音播放时当前人物不能跟着对口型。对白不抢话，给接收信息后的反应留时间。配音、口型、屏幕文字等能力以实际工具为准，不能把要求当成功。

画幅、时长、模型、分段与预算按当前项目和实时工具能力决定。不要沿用火影测试的横版16:9、5秒、720P、100积分作为这里的默认授权。完整故事可以由若干生成片段组成，但不能把平台时长限制当成增加切镜的理由。

## 7. 验收与留档

分别记录：故事因果、角色一致性、表演与连续性、技术输出、用户审核。静帧成功不等于视频成功，完整解码不等于表演通过，高赞参考不等于本片流量保证。

优先修错因果、动作、台词归属、状态复原，再修美术细节。物件移走不能自动回来；人物接收信息前不能提前反应；拔摄像头线不等于电脑或网络断电。

有生成授权再使用对应工具，保存实际提示词、输入引用、版本和结果。用户要求统一审核或停在视频前时，完成故事、总板与提示词后停止，不生成视频、不发布。

故事、总板、提示词和采用状态保留在当前本地项目的原位置，更新前读取最新内容；实件与正文回读后才称已保存。Skill方法与项目状态分开。用户另外指定外部表时才按该工具执行，本流程不依赖固定表ID。

生成网络错误时，不从一条错误推断提示词违规、额度不足或全局网络故障。先回查原任务；确有当前授权的重试或诊断范围时，按最小单图、同参考短提示或精简总板等单变量方式检查，不能为排障自动新增付费任务。当前案例短请求成功、长请求失败，仅说明存在可用路径，不构成长度上限或根因证明。

只有用户要求记录、从工作台排队任务续接，或当前项目已选用工作台时，才读取 `seedance-prompts` 的 `references/studio.md`，沿同一 task/run 保存进度与候选。普通创作、采集与字幕直接在当前任务交付；工作台未配置不阻塞这些工作，也不替代原项目状态。
